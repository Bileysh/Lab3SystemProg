# Транслятор підмножини мови C на базі Lex/YACC (C# / .NET)

Лабораторна робота №3 з системного програмування. Синтаксичний аналізатор мови C,
побудований генераторами **GPLEX** (аналог Lex/Flex) та **GPPG** (аналог YACC/Bison, LALR(1))
для платформи .NET, з семантичним аналізом, інтерпретацією AST, трансляцією у **JavaScript**
та візуалізацією AST у браузері на **d3.js**.

| Вимога завдання | Що зроблено |
|---|---|
| Синтаксичний аналізатор на Lex/YACC | `CLexer.lex` (GPLEX) + `CParser.y` (GPPG, LALR(1)): 120 правил, 213 станів, **0 конфліктів** |
| Граматика мови C | функції, прототипи, глобальні/локальні змінні, масиви (у т.ч. багатовимірні), `if/else`, `while`, `do-while`, `for`, `break/continue/return`, усі операції C з правильними пріоритетами, `?:`, приведення типів, `#define` |
| Теорія: LALR, yacc, конфлікти | таблиця `%left/%right/%nonassoc`, `%prec`, траса shift/reduce, HTML-звіт станів автомата, окремий проєкт `Theory` з демонстрацією S/R та R/R конфліктів |
| Семантика / обчислення | семантичний аналіз (таблиця символів, області видимості, типи, 15+ видів помилок) та **інтерпретатор AST** |
| Генерація коду на цільовій мові | трансляція C → **JavaScript**, запуск у Node.js та у браузері (Web Worker) |
| Візуалізація AST | інтерактивне дерево на **d3.js** у веб-браузері: згортання вузлів, масштаб, підказки з типами, зв'язок з рядками коду, експорт SVG |

## Швидкий старт

Потрібно: **.NET SDK 10** (GPPG/GPLEX підтягуються NuGet-пакетом `YaccLexTools` автоматично).
Необов'язково: **Node.js** - для запуску згенерованого JS з консолі та в тестах.

```bash
dotnet build
```

```bash
dotnet run --project src/CCompiler.Web
```

Відкрити http://localhost:5002 - редактор, AST, лексеми, траса LALR, JavaScript, виконання.

```bash
dotnet run --project src/CCompiler.Cli -- examples/factorial.c --ast --js
```

```bash
dotnet run --project src/Theory
```

```bash
dotnet test
```

Опції CLI: `--tokens`, `--ast`, `--js`, `--trace` (траса shift/reduce), `-o out.js`,
`--json ast.json`, `--no-node`.

автомата, і `CParser.conflicts`). Згенеровані файли не зберігаються в git.

## Підтримувана підмножина C

* типи: `int`, `char`, `float`, `double`, `void`, `long`, `short`, `unsigned`, `signed`, `const`, `bool`;
* масиви `int a[10]`, `double m[3][3]`, `char s[] = "text"`, списки ініціалізації `{1, 2, {3}}`;
* функції з параметрами-масивами (`int a[]`, `double m[][3]`), рекурсія, прототипи, `f(void)`;
* оператори: блоки, `if/else`, `while`, `do-while`, `for` (з оголошенням у `for`), `break`, `continue`, `return`;
* вирази: `= += -= *= /= %= &= |= ^= <<= >>=`, `?:`, `|| &&`, `| ^ &`, `== !=`, `< > <= >=`,
  `<< >>`, `+ -`, `* / %`, унарні `- + ! ~ ++ --`, постфіксні `++ --`, `a[i]`, виклики, `(type)x`;
* літерали: десяткові/вісімкові/шістнадцяткові цілі, дійсні з експонентою, символи з escape-послідовностями, рядки (склеювання сусідніх);
* бібліотека: `printf` (`%d %i %u %o %x %X %f %e %g %c %s %%`, прапорці, ширина, точність), `puts`, `putchar`, `abs`, `fabs`, `sqrt`, `pow`, `floor`, `ceil`, `sin`, `cos`, `exp`, `log`;
* препроцесор: `#include` ігнорується, `#define NAME значення`.

Не підтримуються: вказівники, `struct/union/enum`, `switch`, `goto`, `typedef`, введення (`scanf`).

## Теорія (коротко)

**Lex/GPLEX.** Набір регулярних виразів → НСкА → ДСкА (детермінізація, мінімізація).
`yylex()` читає найдовший префікс, що відповідає якомусь шаблону; при рівній довжині
перемагає шаблон, записаний раніше (тому ключові слова стоять перед `{L}({L}|{D})*`).

**YACC/GPPG.** За граматикою будується LALR(1)-автомат: канонічна система LR(0)-множин
пунктів + lookahead-символи (LALR = LR(1) зі злиттям станів з однаковим ядром).
Результат - таблиці ACTION (shift *s*, reduce *r*, accept, error) і GOTO.
Розбір - автомат із магазинною пам'яттю: на стеку стани; *shift* переносить лексему і
переходить у новий стан; *reduce A → β* знімає |β| станів, виконує семантичну дію
(`$$ = …`) і переходить за GOTO[стан, A].

**Конфлікти.**
* *shift/reduce* - в одному стані на тій самій лексемі можливі і перенесення, і згортка.
  yacc за замовчуванням обирає **shift** (і повідомляє). Розв'язується пріоритетами:
  пріоритет правила (останній термінал або `%prec`) порівнюється з пріоритетом лексеми:
  вищий у лексеми → shift, вищий у правила → reduce, рівні → асоціативність
  (`%left` → reduce, `%right` → shift, `%nonassoc` → помилка).
* *reduce/reduce* - можна згорнути за двома правилами. yacc обирає **правило, записане раніше**;
  зазвичай це сигнал переписати граматику.

У проєкті: таблиця пріоритетів у [CParser.y](src/CCompiler/Parsing/CParser.y) (рядки 18-33),
«висячий else» через `%prec IFX` (рядок 165), унарні операції через `%prec UNARY`.
`dotnet run --project src/Theory` показує: калькулятор без пріоритетів має 20 S/R конфліктів
і обчислює `1-2-3 = 2`, «висячий else» дає 1 S/R, граматика LR(1)-але-не-LALR(1)
і реальний випадок `f(void)` дають R/R.

## Семантика та генерація коду

**Семантичний аналізатор** будує стек областей видимості (глобальна → функція → блок → `for`),
зв'язує кожен `Ident` з `Symbol`, обчислює `CType` кожного виразу і повідомляє про:
неоголошені та повторно оголошені імена, неправильну кількість/типи аргументів, присвоєння не-lvalue
і масивам, зміну `const`, `%`/бітові операції з `float`, `break/continue` поза циклом, `return`
зі значенням у `void`-функції, відсутність `main`, неконстантний розмір масиву (+ попередження).

**Інтерпретатор** обходить AST: `long` для цілих (ділення до нуля, як у C), `double` для дійсних,
`CArray` для масивів (передаються за посиланням), неявне `(int)` при записі в цілу змінну,
контроль меж масивів, ліміт кроків і глибини рекурсії.

**Генератор JavaScript** зберігає структуру програми, а відмінності мов закриває за типами з sema:

| C | JavaScript |
|---|---|
| `a / b` (цілі) | `_idiv(a, b)` → `Math.trunc(a / b)` |
| `int x = 3.99;` | `let x = Math.trunc(3.99);` |
| `a < b` як значення | `Number(a < b)` (0/1 замість true/false) |
| `a && b` як значення | `a && b ? 1 : 0` |
| `==`, `!=` | `===`, `!==` |
| `int a[3][3];` | `let a = _arr([3, 3], 0);` |
| `char s[] = "hi";` | `let s = _arr([3], 0, "hi");` |
| затінення `{ int x; { int x; } }` | `let x … let x_1` (через TDZ у `let`) |
| `printf` | `_printf` (власна реалізація форматування, ідентична C#-інтерпретатору) |

Коректність трансляції перевіряє тест `GeneratedJavaScriptMatchesInterpreter`: для кожного прикладу
вивід згенерованої програми в Node.js має збігатися з виводом інтерпретатора.

## Обмеження

* цілі числа: інтерпретатор використовує 64-бітні `long`, JavaScript - `double` (точно до 2^53);
  переповнення `int` не моделюється;
* немає вказівників і структур; рядки - масиви `char` з `'\0'`;
* у складеному присвоєнні елемента масиву з побічним ефектом в індексі (`a[i++] /= 2`)
  згенерований JS обчислює індекс двічі.
